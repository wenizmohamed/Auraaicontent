## What's new for users

### Three-pane workspace at `/workspace`

Linear/Notion-style layout: 64 px collapsed sidebar / 240 px expanded,
middle list, right detail pane. Six real surfaces, all backed by live
data:

| Surface | Where the data comes from | What you see |
|---|---|---|
| Calendar | `calendarApi.getMonth()` | Months list + per-day grid w/ post counts, clickable through to detail |
| Strategy | `briefsApi.list` + `knowledgeApi.list` | Brief feed + per-brief knowledge items |
| Studio | `assetsApi.list` | Asset thumbnails (image/video) + preview |
| Insights | `dashboardApi.stats` + `aiStats` | Metric tiles + AI-engine bento + provider-router orbital |
| Settings | `orgsApi.list` + `billingApi.checkout/portal` | Profile / Members / Billing / API keys |
| Content | `contentPiecesApi.list` (legacy bridge) | Drafts queue (drag into Calendar) |

The legacy top-level routes (`/calendar`, `/dashboard`, etc.) still
work and remain the editing surfaces — `/workspace` is the new
read-and-navigate shell.

### Agent surface at `/agent`

Brand-new route, lazy-loaded, available to anyone with a session.

- **Plan tab** — `AgentPlanView` renders a multi-step plan with
  status icons (✓ done, ↻ in-progress, · pending, ✗ failed),
  collapsible substeps, dependency arrows, Approve / Cancel buttons.
  Currently hydrated from a sample plan; will accept the
  `/api/agent/sessions/:id/plan` payload once that endpoint lands.
- **History tab** — Left rail of past sessions (260 px), right pane
  with `SessionTrace` — a chronological merge of the session's
  messages + events with collapsible JSON payload previews. Backed by
  the existing `/api/agent/sessions/:uid` endpoint.

### Per-org monthly spend gate (Phase 4)

- New `Organization.monthlyAiBudgetUsd Decimal(10,2) @default(0)`
  column. Migration applied via `prisma migrate deploy` (had to
  hand-write the SQL — shadow DB blocked by the `vector` extension).

  `OrgBudgetExceededError` (statusCode 402, code
  `org_budget_exceeded`).

  `await assertOrgBudget(meta?.orgId)` BEFORE dispatching to any
  provider. Budget = 0 means no enforcement (all existing orgs are
  unaffected).

### Agent template registry

- New `server/src/agent/templates.ts` — typed registry of three
  opinionated agent templates:
  - **Docs Assistant (Brand Q&A)** — RAG-grounded; refuses to invent
    facts not in the corpus; Kimi preferred for long context.
  - **Structured Extractor** — paste PDF / email / transcript →
    typed JSON; Gemini preferred.
  - **Research → Write** — three-stage (researcher → writer →
    editor) producing a sourced, on-brand piece.
- New REST: `GET /api/agent/templates` (catalog) +
  `GET /api/agent/templates/:id` (full record incl. system prompt).
  Auth-gated under the existing agent router.
- Frontend: `agentApi.listTemplates()` + `getTemplate(id)` on
  `lib/backend-api.ts`. RadixAssistant fetches the catalog on mount
  and renders one-click launchers in its empty-state.

### Session replay infrastructure

`SessionTrace` consumes the existing `AgentEvent` table data already
persisted at `realtime/io.ts:196`. No backend changes needed — the
`/api/agent/sessions/:uid` endpoint was already returning up to 500
events + all messages; the frontend just needed a UI to render the
chronological merge.

- Video generation re-routed to Grok primary (was Gemini before;
  Grok's video quality has surpassed at this tier).
- Telemetry circular buffer in `ai-router.ts` exposes per-provider

## Migration notes

### `npm install` after pulling

The lockfile had drifted (server deps missing from root hoist). After
`git pull`, run **from the repo root**:

```bash
cd /opt/radixcontent && npm install
```

This is required by npm workspaces — adding deps to `apps/desktop` or
`server` doesn't propagate unless install runs from root. **Don't
`cd server && npm install`** — it'll create a half-installed local
`node_modules` that the workspace tooling will fight with.

### Production deploy unchanged

Nothing in this 2-day push changes the deploy flow. Per `CLAUDE.md`:

```bash
# Server
cd /opt/radix-v2/server && npm run build && pm2 restart radix-api

# Frontend
cp -r /opt/radix-v2/frontend/dist /opt/radix-v2/frontend/dist.bak-$(date +%s)
cd /opt/radixcontent/apps/desktop && ELECTRON=true npx vite build
rm -rf /opt/radix-v2/frontend/dist
cp -r /opt/radixcontent/apps/desktop/dist /opt/radix-v2/frontend/dist
```

The `/opt/radix-v2/server` directory has its own `node_modules` — do
not symlink to the source tree.

### Prisma migration applied to prod

Migration `20260430170825_add_org_ai_budget` adds the
`monthlyAiBudgetUsd` column to `Organization`. Already applied via
`prisma migrate deploy` (hand-written SQL because the shadow DB is
blocked by the `vector` extension). Mirrored to
`/opt/radix-v2/server/prisma/migrations/`.

### JWT TTL unchanged

Default access token: 1 hour. With "Remember me": 7 days. Refresh
tokens: 30 days. The frontend auto-refreshes on 401 (silent retry).
